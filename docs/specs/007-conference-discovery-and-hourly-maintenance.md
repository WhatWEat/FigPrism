# 007 — 会议目录冷启动与每小时自动巡检

- **Status**: `In Progress`
- **Created**: `2026-11-14`
- **Target PRD Sections**: `§6 / §7.3 / §8 / §9`

## 1. 问题与授权

用户要求修复冷启动慢、没有 CVPR 论文，并每小时巡检、有问题自动修复。
现有检索只取当年 arXiv 最近提交结果，无法覆盖会议全年论文。
整批核验屏障阻止已核验论文先入库；任务附着 API 容器，部署会终止任务。

## 2. 范围

- 从 CVF 官方 CVPR 主会目录按会议年份召回。
- 严格排除 Findings、Workshop 与非官方域名。
- 以官方论文页标题、作者、摘要、PDF 和年份构建元数据。
- 根据激活领域词库匹配，保留论文来源链接。
- 可直接下载官方 CVF PDF，不依赖论文必须有 arXiv 版本。
- 已知会议录用候选先处理，补充核验不阻塞它们。
- 核验设总时限；已有候选结果持久缓存，重启可继续。
- 冷启动在独立容器中运行，不随 API 容器重建中断。
- CLI 冷启动记录真实任务进度，异常退出不保留虚假运行状态。
- 继续使用本地先行持久化与后台备份，继承 3 GB 预算。

## 3. 每小时巡检

- 在系统 cron 每小时执行，使用 flock 避免重叠。
- 检查当前生产 API 与 uploader 容器健康。
- 冷启动尚未覆盖全部领域/会议、容器异常退出或中断时恢复。
- 检查批次进度，识别无进程对应的遗留 running/queued 状态。
- 校验原文/图表本地可读、待上传资产不缺失。
- 清理已备份的 LRU 缓存，未上传内容禁止清理。
- 检查远端失败队列，对可恢复情况重试。
- 修复已识别的远端非法文件名，保持数据库与队列引用一致。
- 所有自动操作记录到本地运维日志，输出不含凭据。
- 不能自动修复的错误明确记录，不声称已恢复。
- 只管理本项目的容器、任务、队列与缓存。

## 4. 安全与兼容

- 学术抓取白名单新增精确 CVF 官方域名，逐跳限制仍有效。
- 不执行论文源码、不开放新公网端口。
- 不改账号权限、会话或用户私有内容。
- 不将运行态、账号配置和缓存提交到 Git。
- 不合入主 PRD，等待用户验收。
