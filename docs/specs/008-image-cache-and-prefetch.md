# 008 — 图表分层缓存与浏览预取

- **Status**: `In Progress`
- **Created**: `2026-11-14`
- **Target PRD Sections**: `§3 / §8`

## 1. 目标

用户要求优化点开每张图都要等待的问题，采用 LRU 或适合图表的缓存。
资产磁盘缓存继续共享 3,000,000,000 字节预算。
不改变取色使用原始高清像素的要求。

## 2. 缓存层次

- 浏览器保留有限个已解码高清图，按访问顺序淘汰。
- 按解码像素内存估算限制，而非仅计算压缩后的 WebP 文件大小。
- 主动选中图片请求优先，相邻图预取降低优先级。
- 同 URL 的加载与解码共用 Promise，避免重复请求和重复解码。
- 相邻前后两张适度预取，避免全库预取占满网络和内存。
- 卡片悬停时预热即将打开的高清图与元数据。
- 从缓存重开图片时避免重新走完整加载状态。
- 切换期间继续保留旧图，缩略图/高清图渐进替换。

## 3. 服务器磁盘缓存

- 未备份文件继续固定保护，绝不被淘汰。
- 总预算内专门预留 500 MB 收藏图表池，普通缓存预算为 2.5 GB。
- 收藏池保存收藏图表的缩略图与高清图，池内超限按 LRU 淘汰。
- 收藏变更自动重新分类；后台逐步预热收藏图片，不依赖用户逐张点开。
- 已备份资产中优先淘汰原文、矢量 PDF 与过期元数据。
- 高清图保留访问热点；缩略图作为较小的高命中率层优先保留。
- 全局容量仍受同一限额约束，不设无限缩略图目录。
- 远端同一 key 缓存未命中时合并回源，避免并发重复下载。
- 回源后缓存再读，避免后续请求重复远端读取。
- 已命中资产读取避免等待后台磁盘写入的全局锁。

## 4. 安全与兼容

- 图表版本 URL 仍校验 version_hash。
- HTTP immutable 缓存头与原始图片字节保持一致。
- 私有与管理接口继续 private,no-store。
- 解码缓存按完整 URL 含版本号索引，不混用重切前后的图像。
- 网络失败不永久缓存，允许重试。
- 所有显示混合不影响原始像素取色。

## 实际验证

- 本地资产读取约 6–10 ms；生产域名样本高清图约 60–120 ms（服务器侧采样，非用户网络保证）。
- 收藏池隔离、池内 LRU、取消收藏、后台预热、并发回源合并、读命中不等写锁等后端验证通过。
- 浏览器验证重开同图不增加高清 decode 次数，切图过滤和慢图切换不回退通过。
- 缓存预填后出现的弹窗挂载时序问题已通过节点回调绑定修复，补跑缩放与取色回归。
- 配置 favorite_cache_bytes=500000000、cache_max_bytes=3000000000 已落地。

- 最终生产浏览器 4 项回归全部通过：解码复用、筛选保持、慢图切换、原始像素取色与缩放拖动。
- 最终后端 58 项测试通过，生产构建与类型检查通过。
- 当前 500 MB 收藏池与 2.5 GB 普通池已部署；不修改主 PRD，待用户验收。
