# 018 — 邀请链接使用次数

- **Status**: `In Progress`
- **Created**: `2026-11-16`
- **Target PRD Sections**: `§3.2 用户管理 / §4 注册邀请 / 管理 API`

## 1. 背景

- 用户希望邀请链接支持使用次数。
- 当前所有链接仅允许注册一次。
- 本次提供创建时的次数上限与已用、剩余次数。

## 2. 范围

- 管理员生成邀请时可以设置允许注册人数。
- 默认 1 次，允许 1–1000 的整数。
- 有效期仍为 7 天。
- 展示最近 20 条邀请的已用、上限、剩余次数与状态。
- 页面每 5 秒刷新次数，刷新页面后仍可查看。
- 保留复制邀请链接功能。
- 不增加无限使用、修改既有配额或邀请撤销功能。
- 不修改账号角色、密码规则和缓存策略。

## 3. 交互

- 用户管理“账号与邀请”区增加“可使用次数”输入框。
- 创建中禁用按钮，成功后刷新邀请列表。
- 邀请显示“已用 X / N 次 · 剩余 Y 次”。
- 明确区分可使用、已用完和已过期。
- 过期链接的剩余有效次数为零。
- 空列表和读取失败单独显示。
- 邀请链接仅对管理员可见。
- 沿用暖纸表面与现有语义色彩。

## 4. 数据契约

- invite_codes 新增 max_uses INTEGER NOT NULL DEFAULT 1。
- invite_codes 新增 used_count INTEGER NOT NULL DEFAULT 0。
- 旧邀请默认上限为 1，已使用记录迁移为 used_count=1。
- used_by 保留兼容，记录最近一次成功注册的账号。
- 幂等迁移不会重置现有次数。
- POST /api/admin/invites 接收可选 JSON {max_uses:整数}。
- 原有空请求保持默认 1 次。
- 响应新增 max_uses、used_count、remaining_uses 和 status。
- GET /api/admin/invites 返回最近 20 条邀请及次数。
- 两个接口 require_admin，返回 private,no-store。

## 5. 注册与并发

- 注册校验有效期及 used_count < max_uses。
- 创建用户与消耗次数在同一个 BEGIN IMMEDIATE 事务中完成。
- 并发竞争最后一个名额时只允许一次成功。
- 用户名重复、参数错误等失败不消耗次数。
- 次数用完与过期统一返回邀请不可用错误。
- 不向未登录访客开放邀请列表。

## 6. 验收

- 默认单次邀请保持兼容。
- 多次邀请恰好允许指定人数注册。
- 验证到期、额度耗尽、失败不扣额度和并发竞争。
- 验证旧数据迁移与重复初始化。
- 验证管理权限、非法次数及列表刷新。
- 后端测试、类型检查、生产构建与相关 E2E 通过。
- 分阶段 commit，按用户要求 push 到 origin/main。
- 测试后部署并检查，不提前合入主 PRD。
