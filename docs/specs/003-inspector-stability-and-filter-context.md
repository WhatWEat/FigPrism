# 003 — 检视器稳定切图与筛选上下文

- **Status**: `In Progress`
- **Created**: `2026-11-14`
- **Target PRD Sections**: `§3.2 / §9.2`

## 1. 背景与痛点

- 同篇论文切换 Fig 时，详情查询进入 pending，整块工作台被替换成加载页。
- 从方法图或实验图筛选进入后，同文导航却显示全部图，分类边界丢失。
- 用户希望切图稳定，并能明确区分当前分类与同文其他图片。

## 2. 本次范围

- 保持检视器布局和已显示图像，下一张图解码后再替换。
- 先使用已缓存缩略图展示目标图，再无空白替换高清图。
- 预取相邻图的资源，避免重复展开加载页。
- 从 Deck、Swimlane、Flat 进入时携带当前筛选条件。
- 同文导航默认仅列出当前筛选命中的图。
- 提供明确的“查看同篇全部图表 / 仅看当前筛选”入口。
- 全部模式标记未命中当前筛选的图。
- 导航缩略项和当前图面板展示图表分类。
- 本单不调整提图算法、并发配额和账号权限。

## 3. 交互规则

- 首次打开可以显示加载状态；切图不卸载工作台主体。
- 异步请求乱序时，只显示最新选中的目标。
- 高清加载中显示轻量状态，保留可读的图像预览。
- 高清不可用时保留缩略图并提示。
- 原始高清像素未就绪时禁用吸管，避免把缩略图色值当原色。
- 相邻缩略导航、↑/↓ 与左右切图保留入口筛选上下文。
- 从“全部”回到筛选模式时，若当前图不匹配，定位到首个命中图。
- 收藏夹、历史页等无筛选上下文的入口继续显示同文全部图。
- 两种导航范围均使用清晰的图号、分类、计数和选中标识。

## 4. 接口增量

- `GET /api/papers/{pid}/figures` 接受与 Feed 一致的筛选参数。
- 包括领域、子标签、会议、版式、图形类型、色系、关键词及快捷视图。
- 未传筛选参数时保持返回全部同文图表的兼容行为。
- 返回 `items`、`matched_count` 和 `total`（同文所有图表数）。
- 不按 Feed 当前页截断同文匹配结果。
- SQLite 表结构、存储资产与 CLI 无变更。
- 原始图像、色板和离屏取色继续保持像素保真。

## 5. 验收

- 方法入口同文导航只列 Teaser、Pipeline、Micro-Mechanism。
- 数据入口同文导航只列 Curve、Bar、Scatter/Radar、Heatmap。
- 其他筛选组合在检视器里继续生效。
- 全部模式能看到并辨认其他分类，回切时正确定位。
- 人为延迟高清请求时，工作台和图像节点仍存在且保持可见。
- 快速连续切图不会由较慢的旧请求覆盖最新选择。
- 原始像素取色、收藏、子图聚焦与重切回归通过。
- 后端测试、前端类型检查、生产构建和 E2E 通过。
- 用户验收后再将最终契约合入主 PRD。
