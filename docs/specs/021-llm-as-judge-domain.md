# 021 — LLM-as-a-Judge 研究领域词库

- **Status**: `In Progress`
- **Created**: `2026-11-18`
- **Target PRD Sections**: `§5 动态可扩展领域引擎`

## 1. 背景

- 用户要求新增 LLM-as-a-Judge 领域。
- 目前该方向与后训练、推理等领域存在交叉，缺少独立筛选入口。
- 本单仅记录领域词库增量，不记录每次抓取批次数。

## 2. 范围

- 新增 llm-as-judge 领域，展示名 LLM-as-a-Judge。
- 使用现有动态领域配置与管理接口契约。
- 保留全部已有领域及其启停状态。
- 前端从 domains API 自动加载该领域。
- 不修改领域匹配算法、数据表或前端组件。

## 3. 主题边界

- 语言模型充当评判器或自动评价器。
- 评判器训练、蒸馏与泛化。
- 评分标准、Rubric 与成对比较。
- 评判偏差、鲁棒性、校准与一致性。
- 与人类偏好对齐、元评估和排行榜可靠性。
- 多模态、代码和 Agent 输出的模型评判。
- 不因普通论文仅出现 evaluation、judge 或 reward 就纳入。
- 不把法律判决预测、人的道德判断自动当作模型评判器研究。

## 4. 配置

- slug: llm-as-judge。
- name: LLM-as-a-Judge。
- is_active: true。
- arxiv_cats: cs.CL / cs.AI / cs.LG。
- phrases 覆盖常见连字符、单复数及自然语言写法。
- 缩写只采用明确的评判器方向标识。
- sub_tags 提供训练、标准、偏差校准、人类一致性与成对评估分类。
- vlm_criteria 要求图表和图注支持标签，避免泛化打标。
- 通过现有 save_domains 同步 SQLite 与 config/domains.yaml。

## 5. 兼容

- 论文可同时属于该领域与原有领域。
- 不自动重标历史论文，不修改已收藏图表与用户数据。
- 使用现有下载、切图、视觉判图与缓存预算。
- 不要求重启在线服务。

## 6. 验收

- 用户验收后再同步主 PRD。
