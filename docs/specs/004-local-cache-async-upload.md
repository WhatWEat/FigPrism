# 004 — 本地持久缓存与异步 WebDAV 备份

- **Status**: `In Progress`
- **Created**: `2026-11-14`
- **Target PRD Sections**: `§7.3 / §8 / §9`

## 1. 背景与目标

远端 WebDAV 慢传占用论文处理槽，阻止图表发布。
用户要求先走本地缓存与异步上传，本地缓存控制在 3 GB 内。
本单依照用户本次授权，替代 AGENTS §4.1 的远端先行发布要求。
主 PRD 暂不改动，待用户验收后合入。

## 2. 本次范围

- 本地原子落盘、持久上传队列、独立后台上传进程。
- 原文与单张图全部资产落盘后，即可发布索引和 SSE。
- 论文解析完成与远端备份完成分开记录。
- 读取优先本地，远端回源后按剩余容量缓存。
- 缓存统一计入缩略图、高清图、原文、元数据、待上传资产。
- 旧缓存目录纳入同一空间预算，逐步按 LRU 清理。
- 不切换存储商，不增加挂载软件，不改变权限和版本缓存契约。

## 3. 容量与持久性

- 默认及生产配置上限为 3,000,000,000 字节。
- SQLite、模型与有生命周期的计算临时目录不属于资产缓存。
- 未备份文件禁止淘汰；空间不足时生产者等待后台腾出空间。
- 已备份文件按最近访问顺序清理。
- 远端回源响应不因缓存写入空间不足而失败。
- 原子替换前 fsync 文件，替换后 fsync 目录，再提交队列记录。
- 同一内容共用本地 blob，避免元数据/相同资产重复占用。
- 重启保留待上传状态，成功前不得清除唯一副本。

## 4. 数据与运维

- 幂等新增 asset_transfers 表，记录 key、内容摘要、大小、类型、
  同步状态、重试次数、下次尝试时间及错误。
- 内容版本变化时旧上传不得误标新版本已完成。
- 同 key 上传跨进程串行，其他 key 可并发。
- metadata.json 仅在当前论文其他资产无待备份项时上传。
- 原文真正上传成功后更新 papers.pdf_uploaded。
- 备份失败有持久退避重试，不占论文处理并发。
- 新增 storage worker/status CLI，Compose 托管独立上传服务。
- /api/admin/pipeline 增加 storage 汇总，维持 private,no-store。
- 有待备份数据时拒绝从远端重建，避免旧快照覆盖本地新内容。
